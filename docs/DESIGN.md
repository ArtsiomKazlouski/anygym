# Трекер тренировок — схема данных и движок веса

Документ описывает то, что работает, а не то, что задумывалось.
Сверен со схемой базы и кодом 16 сентября 2026 года.

## 1. Задача

Пользователь тренируется в трёх залах с разным оборудованием. Килограммы на грузоблоке
одного производителя не сравнимы с килограммами на другом (разные плечи рычага, трение,
единицы стека). Из-за этого:

- нет объективной прогрессии — вес «плавает» вместе с залом;
- каждая незнакомая железка настраивается заново на глаз → травмы;
- перерывы в 1–2 занятия сбивают самооценку нагрузки.

**Приложение отвечает на один вопрос: какой вес поставить прямо сейчас на этой железке,
как её настроить и сколько повторов сделать.**

Принцип: килограммы между разными железками не пересчитываются никогда. История висит
на упражнении, а упражнение привязано к одной модели оборудования — поэтому «сорок»
на бабочке и «сорок» на кроссовере не встречаются в одном расчёте. Между залами
переносится не число, а сама модель: если тот же тренажёр стоит в двух залах,
это одна железка и одна история.

## 2. Ключевые решения

| Решение               | Выбор                                                                   |
| --------------------- | ----------------------------------------------------------------------- |
| Главная работа        | Подсказка веса, а не просто журнал                                      |
| Единица прогрессии    | Пара «упражнение + исполнение тренажёра»                                |
| Идентификация железки | Тип тренажёра → исполнения → залы; упражнение держится за тип           |
| Фидбек                | Повторы + три кнопки запаса (маппятся в RIR)                            |
| Прогрессия            | Двойная + авторегуляция между подходами                                 |
| Анти-травма           | Память настроек тренажёра, флаг боли, откат за паузу по мышечной группе |
| Структура             | Упражнение = подводка + рабочие подходы одним весом                     |
| Платформа             | PWA, online-only (слой записи изолирован под будущий офлайн)            |
| Стек                  | Next.js / Vercel / Neon Postgres / Auth.js + Google, allowlist          |
| Фото                  | WebP ≤400px прямо в колонке БД                                          |

## 3. Мышечные группы

Список статичный, живёт в коде (`src/lib/muscles.ts`) и в типе `muscle_group` в БД.
У упражнения ровно одна группа — главная. Жим лёжа грузит и трицепс, но считать его
и в грудь, и в трицепс значит удвоить объём и потерять смысл счёта.

| code         | Название       |
| ------------ | -------------- |
| `chest`      | Грудь          |
| `back`       | Спина          |
| `traps`      | Трапеции       |
| `shoulders`  | Плечи          |
| `biceps`     | Бицепс         |
| `triceps`    | Трицепс        |
| `forearms`   | Предплечья     |
| `core`       | Пресс и корпус |
| `glutes`     | Ягодицы        |
| `quads`      | Квадрицепс     |
| `hamstrings` | Бицепс бедра   |
| `adductors`  | Приводящие     |
| `calves`     | Голень         |

Группа делает две вещи:

1. **откат за паузу** — если группа не работала три недели, она детренирована,
   и неважно, на каком тренажёре её тренировали в прошлый раз (раздел 5.3);
2. **объём** — сколько рабочих подходов план даёт каждой мышце; видно на экране плана.

Чего группа не делает — не подбирает замену занятому тренажёру.

### Почему не «паттерн движения»

До миграций `0010`–`0011` вместо группы стоял паттерн: `chest_fly`, `incline_press`,
`biceps_curl` — 21 значение. Смысл был в подстановке: тренажёр занят, приложение
предлагает другое упражнение того же паттерна.

Отказались, потому что подстановка не понадобилась. В реальном плане у каждого
пункта есть роль — начинающее упражнение, продолжающее, завершающее, — и заменять
одно другим осмысленно ровно в одном месте из десяти (сведение на грудь; похоже,
ещё что-то в спине). Ради этого одного случая каждое упражнение приходилось
относить к группе взаимозаменяемых, и каталог показывал, что это не работает:
«Жим узким хватом» лежал в `biceps_curl`, «Тяга гантели в наклоне» — в `rear_delt`.
Поле заполнялось наугад, потому что настоящего ответа для большинства упражнений
не существовало.

Заменить одно другим теперь можно руками: убрать пункт, добавить другое упражнение.
Оба действия и так были — они появились для разгибаний по одной ноге, которые
делаются не каждый раз.

Мышечная группа не является более грубым паттерном и не занимает его место.
Она отвечает на другой вопрос: не «чем это заменить», а «что будет уставшим».
Заменять по группе нельзя — жим и сведение оба «грудь», но жим вместо сведения
это не замена, а другое упражнение.

## 4. Схема БД

Всё изолировано по `user_id`. Схема multi-user с первого дня, доступ ограничен
allowlist по email. Ниже — то, что реально лежит в базе после миграций `0000`–`0016`.

### 4.1 Пользователи и справочники

Таблицы входа (`auth_user`, `auth_account`, `auth_session`,
`auth_verification_token`) заданы адаптером Auth.js и здесь не описываются.
Префикс `auth_` нужен, чтобы сессия входа не путалась с сессией тренировки.

Справочных таблиц больше нет: мышечные группы — это тип `muscle_group` в самой
базе, список живёт в коде (раздел 3). Таблица `pattern` удалена миграцией `0011`.

### 4.2 Оборудование

Три уровня, и каждый отвечает на свой вопрос.

**`equipment_type`** — тип тренажёра: передний блок, верхний блок, гантели,
штанга. То, что человек называет, когда говорит, на чём делает упражнение.
Список один на все залы. Упражнение привязано сюда.

**`equipment_model`** — исполнение: конкретная железка со своим грузоблоком,
рядом весов и фотографией. У двух передних блоков разный рычаг, поэтому числа
на них несравнимы — вес живёт здесь, а не на типе. Одно исполнение может стоять
в нескольких залах, если это буквально та же машина: олимпийская штанга так
и работает, и история по ней переносится между залами.

**`gym_equipment`** — какие исполнения стоят в этом зале.

Почему понадобился тип (миграции `0017`–`0018`): пока упражнение держалось
за железку, один и тот же передний блок в двух залах давал **два упражнения
с одним названием и двумя разорванными историями**. План может содержать только
одно из них, поэтому во втором зале упражнение не появлялось вовсе. Так в базе
завелись две «Тяги» и два «Пресса»; миграция их склеила, разложив подходы
по исполнениям, на которых они делались.

    equipment_type(
      id         uuid pk,
      user_id    uuid fk -> auth_user,
      name       text not null,      -- "передний блок"
      kind       enum('stack','plate_loaded','dumbbell','barbell','cable','bodyweight'),
      created_at timestamptz not null,
      unique(user_id, name)
    )

Мышечной группы у железки нет: группа — свойство упражнения (см. 4.3).

    equipment_model(
      id            uuid pk,
      user_id       uuid fk -> auth_user,
      type_id       uuid not null fk -> equipment_type,
      name          text not null,          -- "жим от груди Technogym, синий"
      brand         text,
      units         enum('kg','lb') not null default 'kg',
      step          numeric,                -- шаг прогрессии
      ramp_step     numeric,                -- шаг подводящих, если грубее (см. 5.1)
      min_weight    numeric,
      max_weight    numeric,
      ladder        numeric[],              -- явный ряд весов (гантели)
      bar_weight    numeric,                -- вес грифа (штанга)
      photo         bytea,                  -- WebP, длинная сторона <= 400px
      photo_mime    text,
      notes         text,
      created_at    timestamptz not null,
      updated_at    timestamptz not null
    )

    gym(
      id            uuid pk,
      user_id       uuid fk -> auth_user,
      name          text not null,
      note          text,
      is_active     boolean not null default true,
      created_at    timestamptz not null
    )

`gym_equipment` — экземпляр модели в конкретном зале и переопределения сетки:
тот же модельный ряд бывает со стеком в фунтах, а гантельный ряд у каждого зала
свой. Пустое поле означает «как у модели», а не ноль.

Единицы нельзя переопределить в одиночку: границы и шаг модели записаны в её
единицах и, оставшись, были бы прочитаны как чужие — сетка молча поехала бы.
Поэтому смена единиц требует задать шаг, минимум и максимум в новых единицах
(либо ряд весов, который задаёт сетку целиком).

    gym_equipment(
      id                 uuid pk,
      gym_id             uuid fk -> gym,
      equipment_model_id uuid fk -> equipment_model,
      location_note      text,              -- "у окна, второй ряд"
      units_override     enum('kg','lb'),
      step_override      numeric,
      ramp_step_override numeric,
      min_override       numeric,
      max_override       numeric,
      ladder_override    numeric[],
      is_active          boolean not null default true,
      created_at         timestamptz not null,
      unique(gym_id, equipment_model_id)
    )

`equipment_setup` — запомненные настройки. По умолчанию на модель (разметка
сиденья одинакова на одинаковых железках), при необходимости переопределяются
для экземпляра в конкретном зале.

    equipment_setup(
      id                 uuid pk,
      user_id            uuid fk -> auth_user,
      equipment_model_id uuid fk -> equipment_model,
      gym_equipment_id   uuid fk -> gym_equipment,   -- null = настройка на модель
      settings           jsonb not null default '{}',
      note               text,
      updated_at         timestamptz not null,
      unique(user_id, equipment_model_id, gym_equipment_id)
    )

### 4.3 Упражнения

**Ключ прогрессии — пара «упражнение + исполнение».**

Упражнение нужно потому, что на одних и тех же гантелях делаются жим под 45°,
жим под 30°, бицепс и молоточки: рабочие веса у них разные, слипаться их истории
не должны. По той же причине не нужно отдельно моделировать односторонние
движения — «разгибание ног по одной» просто другое упражнение со своим весом.

Исполнение нужно потому, что одно и то же упражнение делается на разных машинах:
пресс в одном зале идёт с 85, в другом с 65. Пятьдесят на лёгком рычаге и
пятьдесят на тяжёлом — разные числа, и усреднять их значит вернуть ровно ту
проблему, против которой всё строилось.

    exercise(
      id                  uuid pk,
      user_id             uuid fk -> auth_user,
      name                text not null,     -- "жим гантелей под наклоном 45°"
      muscle_group        enum(chest,back,traps,shoulders,biceps,triceps,forearms,
                               core,glutes,quads,hamstrings,adductors,calves) not null,
      equipment_type_id   uuid not null fk -> equipment_type,
      target_reps         int not null default 12,   -- цель повторов (см. 5.4)
      lead_kg             numeric[],                 -- подводка в килограммах
      lead_percents       numeric[],                 -- либо долями рабочего веса
      is_active           boolean not null default true,
      created_at          timestamptz not null
    )

Заявленного рабочего веса у упражнения нет намеренно. Такое число нужно
угадать заранее, вне зала, — ровно то, от чего приложение должно избавлять.
И оно статично: вписал 36 в сентябре, за месяц дошёл до 26, а в поле всё ещё 36.

Вес первого подхода нового упражнения вводится руками, стоя перед железкой,
где его можно почувствовать. Дальше ведёт история.

**Подводка живёт здесь, а не на пункте плана.** Греешься перед тягой одинаково
в любой день и в любом зале — это свойство движения, как и цель повторов. Пока
подводка стояла на плане (миграции `0012`–`0014`), упражнения, добавленные
на тренировке на ходу, не получали её никогда: у них нет строки в плане,
а на ходу добавляется каждый четвёртый пункт.

Заполнено ровно одно из двух полей, либо ни одного. Разница между ними — про
железку, а не про вкус (5.7).

Колонки `notes` у упражнения нет с миграции `0016`: она пережила две переделки,
так и не получив ни одной формы для ввода и ни одной записи.

### 4.4 Шаблоны

Пункт плана — это упражнение и сколько его делать сегодня. Ни целевых повторов,
ни подводки здесь нет: это свойства упражнения, одинаковые в любом плане (4.3).

Разделение вышло принципиальным: на упражнении то, **чем оно является** —
мышечная группа, цель повторов, подводка; на плане — **сколько его хочет этот
день**: число рабочих подходов и заметка. Четыре подхода тяги на спинном дне
и два на другом — про план. То, что перед тягой греешься с 60 %, — про тягу.

    template(
      id          uuid pk,
      user_id     uuid fk -> auth_user,
      name        text not null,
      is_active   boolean not null default true,
      created_at  timestamptz not null
    )

    template_item(
      id           uuid pk,
      template_id  uuid fk -> template,
      position     int not null,
      exercise_id  uuid not null fk -> exercise on delete cascade,
      sets         int not null default 3,   -- рабочих подходов, все одним весом
      note         text
    )

Схемы («прямая» / «рампа») нет с миграции `0012`. Это были не два способа,
а один: упражнение с пустой подводкой и упражнение с непустой. Пока схема
существовала, при «рампе» поле `sets` игнорировалось, а рабочим считался
ровно один подход — верхний. Подводка уехала отсюда на упражнение
в миграции `0016`.

Альтернатив приложение не предлагает: занятый тренажёр меняется руками — пункт
убирается, на его место добавляется другое упражнение (раздел 3, «Почему не
паттерн движения»). До миграции `0011` здесь были `pattern_code`,
`preferred_exercise_id` и `excluded_exercise_ids`.

Экран плана считает по нему рабочие подходы на каждую мышечную группу: вопрос
«не много ли бицепса и совсем ли нет спины» задаётся при планировании, когда
на него ещё можно повлиять.

### 4.5 Тренировки

    workout_session(
      id           uuid pk,
      user_id      uuid fk -> auth_user,
      gym_id       uuid fk -> gym,
      template_id  uuid fk -> template,      -- null = тренировка без плана
      started_at   timestamptz not null,
      ended_at     timestamptz,              -- null = идёт прямо сейчас
      note         text
    )

    session_item(
      id                uuid pk,
      session_id        uuid fk -> workout_session,
      position          int not null,        -- меняется при «занято»
      template_item_id  uuid fk -> template_item,  -- null = добавлено на ходу
      exercise_id       uuid fk -> exercise, -- null = упражнение удалили из каталога
      equipment_model_id uuid fk -> equipment_model,  -- на чём делалось сегодня
      status            enum('pending','active','done','deferred','skipped'),
      target_sets       int not null,
      extra_sets        int not null default 0,    -- добавленные на тренировке
      rep_min           int not null,
      rep_max           int not null,
      deferred_count    int not null default 0
    )

    set_log(
      id                   uuid pk,
      session_item_id      uuid fk -> session_item,
      position             int not null,
      kind                 enum('warmup','ramp','working') not null default 'working',
      weight               numeric not null,   -- как написано на стеке
      units                enum('kg','lb') not null,
      weight_kg            numeric not null,   -- нормализовано, вся математика тут
      reps                 int,
      feedback             enum('easy','on_target','limit','failed'),
      pain_zone            text,
      prescribed_weight_kg numeric,            -- что предложил движок
      prescription_source  enum('history','declared','probe','manual','deload','pain_backoff'),
      logged_at            timestamptz not null
    )

`prescribed_weight_kg` и `prescription_source` хранятся не для интерфейса,
а чтобы потом честно оценить, насколько движок угадывает.

Удаление каскадное: тренировка уносит свои пункты, пункт — свои подходы.

### 4.6 Производное состояние

Отдельной таблицы состояния прогрессии нет, всё выводится из `set_log`:

- **рабочий вес упражнения** = `weight_kg` последнего `working`-подхода по этой
  паре `exercise_id` + `equipment_model_id`, **который не был провален**. Рост внутри сессии (50 → 55
  по фидбеку «легко») должен переноситься, а финальный проваленный подход
  не должен опускать базу дважды — за него уже отвечает межсессионная
  прогрессия из 5.4;
- **дата последней работы на мышечную группу** = максимальный `logged_at` среди
  `working`-подходов, чьё упражнение принадлежит той же группе;
- **заморозка по боли** = был ли `pain_zone` в последних двух сессиях
  на этом упражнении.

Подводящие подходы (`kind = 'ramp'`) и разминка в прогрессии не участвуют.

### 4.7 Фото железки

Лежит в `equipment_model.photo` (bytea) рядом с остальными полями модели.
Нужно не для красоты: это способ узнать в новом зале, что тренажёр тот же
самый, — а без узнавания не работает перенос истории между залами.

**Сжимает браузер, а не сервер.** Снимок с телефона — 3-5 МБ; гнать их наверх,
чтобы уменьшить там, значит платить трафиком в зале, где связь и так так себе.
Перед отправкой картинка ужимается до 400px по длинной стороне и переводится
в WebP, на выходе 60-100 КБ. Поворот берётся из EXIF, иначе снятое боком фото
ляжет повёрнутым.

**Байты не ездят вместе с моделью.** `select()` тянет таблицу целиком, поэтому
все запросы берут явный список колонок без `photo` (`MODEL_COLUMNS`), а наличие
фото отдают флагом. Сами байты идут отдельным маршрутом
`/equipment/[id]/photo`, закрытым той же проверкой входа, что и всё остальное.

Адрес несёт версию — `?v=updatedAt`, — поэтому кэшируется навсегда: поменял
фото, поменялся и адрес.

## 5. Движок веса

Вся математика в `weight_kg`. Отображение — в единицах железки.
Устройство упражнения — подводка и рабочие подходы — в 5.7; всё остальное
в разделе описывает назначение **рабочего** веса.

### 5.1 Дискретизация

    round_to_available(w_kg, gym_equipment) -> достижимый вес

Берёт `ladder_override ?? ladder` если он задан (гантели), иначе `step`/`min`/`max`
с учётом override экземпляра. Для штанги сетка отсчитывается от веса грифа.
Движок не имеет права назвать вес, которого на этой железке физически нет.

Направление округления:

| Случай                                            | Направление                      |
| ------------------------------------------------- | -------------------------------- |
| Рост на ступень                                   | вверх (следующая ступень сетки)  |
| Снижение на ступень                               | вниз                             |
| Назначение веса: откат за паузу, снижение по боли | к **ближайшей** ступени          |
| Подводящий подход                                 | к ближайшей ступени грубой сетки |
| Страховка «не выше опорного веса»                 | вниз                             |

Ближайшая, а не строго вниз — потому что на грубой сетке строгое округление вниз
искажает замысел: шаг 20 кг при рабочих 100 превратил бы откат в −20% вместо
запрошенных −5%. Отсюда следствие, принятое сознательно: **если запрошенное снижение
меньше половины шага, сетка его не выражает и вес остаётся прежним.** Это безопасно —
один подход с фидбеком «легко» и так вернул бы вес на то же место.

Поверх этого действует страховка: назначенный вес никогда не превышает опорный.
Она срабатывает только если опорный вес не лежит на текущей сетке — история пришла
с экземпляра с другим шагом или в других единицах.

**Грубый шаг для подводящих.** Шаг отвечает за две разные задачи: точность прибавки
при прогрессии и округление подводящих подходов. Рабочему весу точность нужна,
подводящему — нет: вешать 82.5 ради разминки значит возиться с блинами по 1.25
на каждой стороне. Поэтому у модели есть `ramp_step`; подводящие и разминка
округляются по нему, рабочий вес — по обычному `step`. У штанги это даёт
20, 60, 80, 90 и верх 102.5.

**Список достижимых весов.** Из той же сетки строится барабан выбора веса в форме
записи подхода: выбрать вес, которого на железке нет, невозможно в принципе.
Если сетка не задана, остаётся ручной ввод.

**Ноль — допустимый вес.** Подтягивание без отягощения это ноль, а не отсутствие
подхода. Турник, на который иногда вешают блины, описывается как `plate_loaded`
с минимумом 0: ноль означает свой вес, остальное — добавку, и прогрессия
работает обычным образом. Тип `bodyweight` оставлен для случая, когда
отягощение не используется никогда: сетки у него нет, расти можно лишь
в повторах.

### 5.2 Маппинг фидбека

После рабочего подхода спрашивается одно — сколько осталось в запасе:

| Кнопка             | Значение    | RIR  |
| ------------------ | ----------- | ---- |
| Легко (мог ещё 3+) | `easy`      | ~3   |
| В точку (ещё 1–2)  | `on_target` | ~1.5 |
| На пределе         | `limit`     | 0    |

После подводящего вопрос другой — идём ли к запланированному рабочему весу,
и кнопок две: «По плану» (`on_target`) и «Тяжелее, чем ждал» (`limit`).
Подписи называют последствие, а не ощущение: подводящий обязан быть лёгким,
спрашивать про запас на нём бессмысленно.

**Кнопки «Не добил» нет.** Она дублировала бы число повторов: восемь при цели
от десяти — это и так недобор. Значение `failed` осталось в типе `set_feedback`
ради записей, сделанных старой формой; провал теперь выводится из повторов
(`isFailed`), а кнопка отвечает на то, чего число сказать не может, — чего
подход стоил.

### 5.3 Назначение веса на первый рабочий подход упражнения

    1. База
       a. Есть история по этому упражнению:
             W = рабочий вес упражнения
             source = 'history'
          Применить межсессионную прогрессию (см. 5.4).
       b. Истории нет:
             ручной ввод, source = 'manual'

    2. Откат за паузу (только для ПЕРВОГО упражнения на данную ГРУППУ в сессии)
       d = дни с последней работы на эту мышечную группу (не на это упражнение)
       d <= 10  -> × 1.00
       11..21   -> × 0.95
       22..42   -> × 0.90
       43..90   -> × 0.85
       d > 90   -> сброс: история устарела, вес спрашиваем заново (ветка 1b)
       source = 'deload' если множитель < 1

    3. Откат за боль
       Если в последних двух сессиях на этом упражнении был pain_zone:
             W = W × 0.9, source = 'pain_backoff'
             UI показывает: "в прошлый раз была боль: <зона>"
       Межсессионный рост при этом заморожен (см. 5.4).

    4. W = round_to_available(W, gym_equipment)   -- к ближайшей ступени,
                                                  -- но не выше опорного веса

**Вес незнакомого упражнения не угадывается.** До миграции `0010` он брался от
соседнего упражнения того же паттерна с коэффициентом 0.6 (`source = 'probe'`).
По мышечной группе так делать нельзя: жим и сведение — одна грудь, но сотня
в жиме не означает сотню в разводке, и промах вверх на незнакомой железке —
это травма. Первый вес называешь ты, стоя перед железкой. Значения `'probe'`
и `'declared'` оставлены в типе: на них ссылаются старые записи подходов.

**Целевые повторы — свойство упражнения, а не плана.** «Тяга гантелей —
двенадцать» верно в любом плане и в любом зале; то, что вышло десять, —
результат, а не другая цель. Поэтому `target_reps` живёт на `exercise`,
а у пункта плана полей повторов нет вовсе.

Одно число и на подводящих, и на рабочих: подводящий отличается весом, а не тем,
сколько раз ты собираешься поднять. Отдельных повторов по ступеням подводки нет
намеренно — решать за человека, как ему разминаться, приложение не берётся.

**Диапазон выводится, а не вводится.** Движку нужны две границы: пока повторы
растут внутри, вес стоит, а закрыл верх — прибавился. Без буфера прогрессия
становится линейной, то есть каждый раз либо плюс вес, либо ничего, и потолок
приходит быстро. Нижняя граница считается как `target_reps − 2`, наружу
не показывается и всплывает только в пояснении, когда вес снижается.

Пункт сессии хранит границы снимком: изменение цели не должно задним числом
переписывать уже проведённые тренировки.

### 5.4 Межсессионная прогрессия

Смотрим **первый подход, сделанный на опорном весе** (опорный — из 4.6):

    повторов меньше нижней границы  -> W -= step
    закрыт верх диапазона           -> W += step
    иначе                           -> W без изменений (растём в повторах)

Заморожено, пока действует откат за боль.

**Почему первый, а не все.** Второй и третий подход на том же весе всегда
слабее первого — это накопленная усталость, а не приговор весу. Требовать
верх диапазона от всех значило бы не дать вырасти никогда, особенно когда
перед работой есть подводка; считать проваленными всех, кто не дотянул, —
наоборот, утягивать вес вниз каждую тренировку. Первый подход единственный
делается из недели в неделю в одинаковых условиях, поэтому сравнивать можно
только его.

**Почему на опорном, а не вообще первый.** Вес внутри тренировки может
вырасти (5.5), и тогда опорным становится уже поднятый. Если судить по
подходу на старом весе, прибавка начисляется дважды — один раз внутри
тренировки, второй между ними.

Случай из жизни: жим узким хватом, 90×9 при цели 8. Вес поднялся до 95 прямо
в тренировке, на 95 вышло 7. Приложение предложило 100 — потому что опору
взяло из последнего подхода, а решение из первого. Девятка была на девяноста,
а прибавку получили девяносто пять. Опорный вес и подход, по которому судим,
обязаны быть из одного места.

**Между тренировками решают повторы, а не кнопка.** Раньше ответ «на пределе»
хоть на одном подходе блокировал прибавку — и прогресс становился невозможен:
последний подход на верхней границе диапазона почти всегда ощущается
предельным, в этом и смысл границы. Пользователь делал 15, 15, 15 при цели 15
и стоял бы на одном весе бесконечно.

Кнопка по-прежнему правит вес внутри тренировки (5.5) — там она к месту.

### 5.5 Авторегуляция внутри упражнения

По фидбеку **предыдущего** подхода:

    easy                          -> W += step
    on_target, повторов > цели    -> W += step
    on_target, повторов <= цели   -> W без изменений
    limit                         -> W без изменений
    повторов < нижней границы     -> W -= step
    pain_zone                     -> стоп: предложить −2 шага либо завершить

Ровно по цели вес внутри тренировки не растёт: рабочие подходы делаются одним
весом, чтобы их можно было сравнить между собой и с прошлой неделей. Прибавку
за закрытую цель выдаёт межсессионная прогрессия (5.4) — один раз, а не дважды
за одну и ту же работу. Больше цели (15 при цели 12) — другое дело: это просто
лёгкий вес, и ждать следующей тренировки незачем.

Отмена отката за паузу: если первый подход после паузы получил `easy`, следующий
подход возвращается к **доотка́тному** весу, а не к «откаченный + шаг». Откат — это
осторожность, а не наказание.

### 5.6 Разминка

Отдельных разминочных подходов нет намеренно.

Разминка нужна по сути в одном движении — штанге, — а там её роль играет
подводка: гриф, 40, 60, 80 и есть разминка, просто записанная. В остальных
упражнениях пользователь сильно не разминается. Держать ради одного случая
отдельный вид подхода, правило «первое упражнение на мышечную группу в сессии»
и связанную с ним бухгалтерию оказалось дороже пользы.

Мышечная группа осталась: она нужна для отката за паузу и для счёта объёма
(раздел 3).

Значение `warmup` в `set_kind` сохранено — по нему читаются старые записи,
но новых не появляется.

### 5.7 Подводка и рабочие подходы

Упражнение состоит из подводки (может быть пустой) и рабочих подходов
(их всегда хотя бы один, все одним весом):

    20 -> 40 -> 60 -> 80   подводка
    90, 90, 90             работа

Подводящие имеют `kind = 'ramp'` и в прогрессии не участвуют. Задаётся подводка
одним из двух способов, и выбор между ними — про железку, а не про вкус:

| Способ                               | Где                | Почему                                                                               |
| ------------------------------------ | ------------------ | ------------------------------------------------------------------------------------ |
| `lead_kg` — килограммы               | штанга, EZ         | ступень стоит блинов, и человек хочет назвать 60 и 80, а не получить 63.7            |
| `lead_percents` — доли рабочего веса | грузоблок, гантели | любая ступень бесплатна, точное число неважно, а подводка едет за рабочим весом сама |

Отсюда и разное округление, и это не мелочь:

- **килограммы кладутся на обычную сетку железки.** Человек уже выбрал числа
  собираемыми из блинов, приложению остаётся страховка от опечатки. Грубый шаг
  (`ramp_step`) к ним не применяется: введённые 90 на штанге с грубым шагом 20
  превратились бы в 80 — то есть приложение переспорило бы человека там, где он
  прав;
- **проценты кладутся на грубый шаг.** Считает их движок, значит его же работа
  сделать результат удобным для блинов: 63 % от сотни должны стать
  шестьюдесятью, а не 62.5, которые пришлось бы собирать мелочью.

Долями хранилась вся подводка с миграции `0010` по `0013`. Отказались, когда
доли от некруглого рабочего веса стали читаться как «66.7, 88.9»: человек
переставал узнавать собственный ввод. Вернулись как один из двух режимов
(`0015`), когда подводка поехала с одной штанги на грузоблоки, — там числа
неважны, а править их руками каждые несколько недель не хочется.

Ступени тяжелее рабочего веса отбрасываются: после отката за паузу подводка
сама укорачивается, подводить уже не к чему. Если рабочего веса ещё нет
(истории нет, вес вводится руками), подводки не будет тоже — подводить не к чему
и считать не от чего.

**Повторы на подводке те же, что в упражнении.** Решать за человека, как ему
разминаться, приложение не берётся: оно не знает ни его привычки, ни того,
как читается подход в три повтора. Цена этого решения известна и принята —
подводка забирает часть повторов у рабочих подходов, и чем ближе верхняя
ступень к рабочему весу, тем больше забирает.

Отсюда же правило прогрессии из 5.4: считает **первый рабочий подход**.
Второй и третий на том же весе всегда слабее — это накопленная усталость,
а не приговор весу.

Подводка существует ради одного вопроса: идти ли сегодня на запланированный
рабочий вес. Если подводящий отмечен «тяжелее, чем ждал», рабочий вес срезается
на ступень — и сразу для всех оставшихся подходов (`capRamp`).

Почему это важно, а не косметика: когда рабочий вес выбирается на ощущение,
потолок задаётся не силой, а осторожностью, и потому не двигается. Подводка
превращает «идти или не идти» в число, которым управляет обратная связь.

Одна поправка, без которой всё ломается на практике: **ступень обязана быть
строго выше предыдущей и строго ниже рабочего веса.** На грубой сетке доли
схлопываются — 0.85 и 0.9 от 100 при шаге 20 дают обе 80. Схлопнувшиеся
выбрасываются.

**Пересчёт под фактический вес.** Веса в форме редактируемые. Если ты поставил
не то, что предложено, остаток едет пропорционально: поставил 88 вместо 80 —
дальше не 90, а 99. Ступени ниже `RE_ANCHOR_MIN_PERCENT` (0.5) ничего
не пересчитывают: подход пустым грифом не говорит о том, каким будет твой верх.

**Срез по ходу.** Если подводящий дался тяжелее ожидаемого, запланированный
рабочий вес сегодня недостижим:

    'не добил' на подводящем   -> рабочие подходы отменяются
    'на пределе' на подводящем -> рабочий вес срезается до одной ступени выше
                                  текущей, и сразу для всех оставшихся подходов;
                                  хотя бы один рабочий остаётся всегда, иначе
                                  прогрессии не за что зацепиться

Поэтому фидбек спрашивается и на подводящих подходах: без него срез мёртв.
В прогрессии подводящие всё равно не участвуют — она смотрит только на
`kind = 'working'`, и только на первый из них (5.4).

### 5.8 Интервал между подходами

Таймера отдыха нет намеренно: пользователь следит за отдыхом по часам и
ориентируется не на время, а на пульс. Но интервал приложение знает бесплатно —
метка времени ставится на каждую запись подхода.

Подпись говорит «через 1:40», а не «отдых 1:40»: отметка ставится в конце
подхода, поэтому в промежуток входит и отдых, и сам следующий подход.
Приложение не должно называть величину точнее, чем умеет её измерить.

Величина нужна не для дисциплины, а как первый подозреваемый, когда повторы
сыплются от подхода к подходу: из литературы это самый доказанный рычаг
(см. раздел 12).

## 6. Примеры «вход → выход»

**Пример 1. Знакомая железка, штатный рост.**
Жим в тренажёре Technogym, диапазон 8–12, шаг 5 кг.
Прошлая сессия: 50×12 easy, 50×12 on_target, 50×12 on_target. Пауза 4 дня.
→ Первый рабочий подход закрыл верх диапазона → W = 55. Откат не применяется.
→ Подсказка: **55 кг, цель 8–12**. После первого подхода 55×9 on_target → второй тоже 55.

**Пример 2. Незнакомое упражнение в новом зале.**
Тяга верхнего блока, истории нет. Есть история по другим упражнениям на спину,
но она ничего не говорит об этом тренажёре.
→ Подсказка: **веса по этому упражнению я не знаю — поставь сам, дальше подхвачу.**
Результат 35×8 easy → второй подход 40. Снова easy → 45. on_target → рабочий найден.

**Пример 3. Пауза 30 дней.**
Жим ногами, рабочий 120 кг, шаг 10 кг, последняя работа на квадрицепс 30 дней назад.
→ Множитель 0.90 → 108 → ближайшая ступень = 110.
→ Подсказка: **110 кг (−10% после перерыва 30 дней), цель 8–12.**
Первый подход 110×12 easy → второй возвращается к **120**, не к 120+10.

**Пример 4. Боль.**
Сведение, 40 кг, второй подход отмечен болью в плече.
→ Упражнение предлагается завершить. Прогрессия по нему заморожена.
→ Следующая сессия: 40 × 0.9 = 36 → ближайшая ступень = 35, с предупреждением
«в прошлый раз была боль: плечо». Рост не возобновится, пока две сессии подряд
не пройдут без боли.

**Пример 5. Подводка и три рабочих подхода.**
Жим лёжа, рабочий вес 90, цель 10 (диапазон 8–10), подводка `60, 80`.
→ `60 × 10`, `80 × 10` подводящими, затем `90 × 8-10` трижды.
Первый рабочий подход вышел `90 × 10` → следующая тренировка начнётся с 92.5.
Если бы он вышел `90 × 7` — с 87.5. Просадка второго и третьего подхода
на решение не влияет.
Пустой гриф в подводке не записан намеренно: разминаться человек умеет сам,
а ступень, которую не надо решать, приложению незачем показывать.

### Выбор исполнения в зале

Пункт тренировки помнит, на каком исполнении делался (`session_item.equipment_model_id`).
Проставляется он так:

- **в зале одно исполнение этого типа** — ставится само при старте тренировки,
  вопроса не возникает;
- **их несколько** — в карточке упражнения появляется ряд кнопок, выбираешь,
  глядя на машину;
- **ни одного** — карточка говорит, что тип в зале не заведён, и предлагает
  добавить железку в «Залах».

После первого записанного подхода выбор заперт: подходы, сделанные на одной
машине, не должны оказаться приписаны другой. Чтобы передумать — удалить
записанное.

Это тот же механизм, что когда-то предлагал заменить упражнение другим
(раздел 3) и был убран. Разница в вопросе: «чем заменить тягу» ответа не имело,
«на каком из двух блоков ты стоишь» имеет, и человек его знает, просто посмотрев
на тренажёр.

## 7. Автомат сессии

    любой    --тап по пункту-->   active     (прежний активный -> done, если
                                              по нему есть подходы, иначе pending)
    pending  --первый подход--->   active
    active   --«Дальше»-------->   done
    active   --«Занято»-------->   deferred   (position -> в конец)
    любой    --сессия закрыта-->   done либо skipped, по наличию подходов

Прежний активный пункт возвращается в очередь, но не теряет сделанного:
если по нему записаны подходы, он становится `done`, а не `pending`. То же
правило при закрытии тренировки — что записано, то сделано; что пусто,
то пропущено. Иначе переход по списку стирал бы результат.

Отдельной кнопки «пропустить» нет намеренно. Она соседствовала с «занято»,
и по звуку подходила лучше — человек жал её, желая вернуться позже, а пункт
закрывался насовсем. Пропуск теперь означает одно: ты завершил тренировку,
не дойдя до него.

Перейти можно к любому пункту тапом. Это же заменяет и перестановку упражнений
местами: порядок в зале не совпадает с планом, а таскать пункты в списке
на потной сенсорной панели — занятие на любителя.

Отложенный пункт ничем не напоминает о себе: он просто уезжает в конец списка,
и к нему возвращаются тем же тапом, что и к любому другому. Отдельного
напоминания при закрытии тренировки нет — незакрытые пункты разбираются
по факту записей: где подходы есть, там `done`, где нет — `skipped`.

## 8. Границы

Приложение — личный журнал и калькулятор нагрузки. Флаг боли собирает историю для
тебя и для разговора с врачом; это не диагностика. Приложение не заменяет тренера
и не оценивает технику.

## 9. Не входит в v1

Графики и аналитика прогресса (только плоская история), офлайн-режим, распознавание
тренажёров по фото, раскладка блинов для штанги, маршрут по залу с учётом занятости,
таймер отдыха.

(Фото тренажёра сделано, см. 4.7.)

### Отложено до условия

Не «когда-нибудь», а по конкретному признаку — чтобы не всплывало в каждом
разговоре и не забылось.

переехать. Поэтому он нужен, но позже — когда в базе будет что вывозить.

## 11. Открытые вопросы

- ~~Односторонние упражнения (одна рука / одна нога)~~ — **решено: отдельного
  моделирования не нужно.** Подход делается сразу на обе стороны, меняется
  только вес. Поскольку прогрессия висит на упражнении, «разгибание ног
  по одной» — это просто другое упражнение со своей историей и своим рабочим
  весом. Ни флага на подходе, ни отдельной сущности, ни удвоения объёма.
- Дроп-сеты и отказные подходы — сейчас не моделируются; `failed` их частично
  покрывает.
- ~~Коэффициент разведки 0.6~~ — **вопрос снят: разведки больше нет** (5.3).
  Вес незнакомого упражнения не угадывается, его называет пользователь.
- Насколько дорого обходится подводка на цели повторов упражнения. Решено в пользу
  читаемости: одинаковые повторы на всех ступенях (5.7). Проверить можно по
  `prescribed_weight_kg` против фактического, когда накопится несколько десятков
  тренировок с подводкой.

## 12. Что говорит литература

Выжимка сделана по ходу работы, когда вставали вопросы «а как правильно».
Влияет на дефолты, но ничего не навязывает: цели выбирает пользователь.

**Диапазон повторов почти не влияет на рост мышц.** Низкие нагрузки (≤60% от
максимума, много повторов) и высокие дают сопоставимую гипертрофию, если подходы
доводятся близко к отказу. Прирост силы в одноповторном максимуме достоверно
выше у тяжёлых нагрузок.

**Близость к отказу: кривая выполаживается около 2 повторов в запасе.** Рост
мышц усиливается по мере приближения к отказу, но после ~2 RIR прибавка почти
исчезает. Для силы связь с близостью к отказу незначима.

**Цена отказа — травмы.** Отказные подходы повышают риск через разрушение
техники и добавляют 24-48 часов к восстановлению. Отказ уместнее на тренажёрах
с фиксированной траекторией, чем на тяжёлых базовых движениях со свободным весом.

**Отдых — самый доказанный рычаг.** Три минуты против одной дают больше и силы,
и мышц. Отсюда 5.8: когда повторы падают, первое, что стоит проверить, — это
интервал, а не вес.

**Способ прогрессии вторичен.** Растить вес при фиксированных повторах или
растить повторы при фиксированном весе — при равном объёме и равной близости
к отказу результат одинаковый. Значит «снизить вес» и «снизить повторы» при
недоборе примерно равноценны, и выбирать надо по сохранности техники.

Источники:
Schoenfeld и др., низкие vs высокие нагрузки, JSCR 2017;
Robinson и др., близость к отказу, Sports Medicine 2024;
Grgic и др., отказ vs не-отказ, JSHS 2021;
Schoenfeld и др., длина отдыха, JSCR 2016;
Plotkin и др., прогрессия весом vs повторами, PeerJ 2022.
